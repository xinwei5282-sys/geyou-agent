# 格优代理端 PRD

版本：V1.8｜日期：2026-10-23｜用途：代理移动端产品、研发与验收基线

本卷承接《殡葬服务工作台 PRD》的代理端模块，以当前会话确认的代理端规则为准。产品正文按业务模块组织；提示词见[《代理端提示词》](geyou-agent-prompts.md)。本文描述产品应有行为，当前实现差异和验证范围统一放在第 12 节，不能据此认定已上线。

## 1. 产品定位与目标

面向生命礼仪服务代理及业务员，提供手机优先的接待与制作工作台。以持续对话收集家属需求，将资料、人像、讣告和报价归入对应客户及逝者档案，让代理在沟通中逐步办理，而不是先填写完整表单才能开始服务。

核心结果是：客户与服务对象关联准确、沟通可继续、资料不散落、制作结果可核对、报价可解释。AI负责整理与建议，系统负责保存、计算和校验，代理负责核对和记录家属确认。

| 目标 | 验收口径 |
|---|---|
| 一次点击开始接待 | 首页进入可输入的对话页，不先展示客户卡或上传功能区 |
| 接待信息有归属 | 明确姓名后形成待核对档案；后续资料、人像沿用关联，不重复建档 |
| 当前办理不重复 | 已有报价或制作卡片时，不再重复显示同类当前办理入口 |
| 产物与确认分开 | 生成结果不自动变成家属采用、发布或成交 |
| 金额可复核 | 系统计算合计；核价、家属确认与付款状态分开 |
| 手机可操作 | 在375px、440px等代表宽度，关键按钮可达、页面不横向溢出 |

尚无生产使用基线，不设虚构的使用率、转化率或服务时效。试点时记录接待到建档完成率、重复档案数、人工纠错数及生成失败率，再确定优化目标。

### 1.1 用户故事

1. 作为代理，我希望一键开始对话，在资料不完整时也能先回应家属。
2. 作为业务员，我希望接待中明确的信息和人像进入对应档案，减少重复录入和串档。
3. 作为代理，我希望当前办理随沟通变化，只看到本轮需要处理的事项。
4. 作为业务员，我希望从客户列表继续原沟通，保留已确认资料和历史。
5. 作为代理，我希望先制作遗照、再选择关联，并能核对不同服装结果后采用。
6. 作为代理，我希望讣告信息和服务电话准确，经家属确认后再公开。
7. 作为代理，我希望套餐有可解释的项目、金额和核价过程，不重复收费。
8. 作为家属，我希望得到尊重、克制的沟通，能够拒绝或暂停，不被未经确认的内容代表。

## 2. 用户、权限与数据范围

| 角色 | 使用内容 | 数据边界 |
|---|---|---|
| 代理主账号／老板 | 本代理客户、接待、制作与报价 | 本代理授权业务 |
| 业务员 | 接待、本人获授权客户及关联产物 | 成员模块权限与客户可见范围的交集 |
| 家属／亲友 | 查看已确认并可公开的讣告、联系代理 | 不访问内部聊天、草稿和客户管理 |

代理端复用既有客户与业务数据，不建立第二套机构或客户库。客户联系人与逝者是不同对象；同一客户可以关联多位逝者，各自的照片、讣告、报价及进度必须隔离。界面隐藏不能替代服务端权限校验。

## 3. 信息架构与页面框架

底部主导航仅为“首页／客户／我的”。首页依次提供“AI接待／纪念遗照／电子讣告／安葬择吉”四个入口，在一屏内展示人物主视觉、四张卡片和底部导航。四个入口整体上移40px；字号、字重和左侧对齐统一。删除“格优礼仪服务”字样，不显示最近沟通或商城。四张卡片左半侧采用浅色区域承载图标和标题，右侧保留配图并柔和渐隐，文字后不透出窗影花叶；安葬择吉采用浅青绿色，与电子讣告暖米金色区分，日历与白花背景保留。

| 页面 | 核心内容与操作 |
|---|---|
| 首页 | 人物主视觉、服务助手标题、四张功能卡及底部导航，一屏展示 |
| AI 接待 | 对话记录、当前办理入口、输入与上传、沟通历史 |
| 沟通历史 | 右侧抽屉、搜索、选择记录继续；无新建接待按钮 |
| 客户列表 | 客户与服务对象摘要、最近沟通、独立“继续沟通” |
| 客户详情 | 家属联系、逝者资料、人像、告别安排、服务产物；删除最近沟通板块，历史从AI接待查看 |
| 资料／上传／八字／套餐 | 独立全屏操作页；保留返回及必要底部操作 |
| 电子讣告 | 列表、详情、资料编辑、模板与内容核对、预览 |
| 纪念遗照 | 列表、新建、任务详情、原图／结果、关联及采用 |
| 安葬择吉 | 首页独立入口、统一记录；择时／择位两个按钮，可单选或同时选择；候选时间与杭州公墓推荐 |
| 我的 | 当前账号、联系电话、资料权限说明、产品说明（PRD）、退出登录 |
| 产品说明（PRD） | 章节选择、业务规则、验收用例及当前实现边界，只读查看 |

“我的”不提供“我的客户／共享演示／机构完整版”入口。客户详情不重复放置“继续沟通”，该操作留在列表。首页不显示右上角新建按钮，客户列表可新建接待。

顶部标题稳定居中；返回与右侧操作保留对称安全留白。列表和主页面使用底部导航，办理页以任务完成与返回为主。长对话、表单滚动不遮挡输入栏或底部主操作。

添加客户资料时，点击“选择照片”区域弹出来源选择，包含“从相册选择”“拍照”和“取消”；不再在页面常驻两颗同类按钮。相册不指定拍摄模式，拍照入口使用移动端相机捕获；实际系统选择器由设备决定。

### 3.1 空状态

代理端列表与套餐准备页统一使用空状态组件：遗照、讣告、客户、沟通历史和套餐准备，图标尺寸、标题/说明、垂直留白一致。区分没有记录与搜索/筛选无结果，后者提供重置筛选入口。无记录不虚构示例数据，不重复提示点击右上角制作。商品详情没有升级候选时继续隐藏推荐区，不显示空状态。

### 3.2 页面查看 PRD

“我的 → 产品说明（PRD）”打开代理端专项文档，可按章节阅读。页面与本Markdown共用一个内容源，显示版本和更新日期；不另存一份可能过期的文案。查看、返回及切换章节不修改客户或业务记录。总工作台的开发PRD继续显示总纲，两者通过文档索引关联。

## 4. AI 接待与持续沟通

接待遵循以下阶段，系统快照是实际业务状态的依据，历史聊天不替代保存或确认记录。

| 阶段 | 页面行为与下一步 |
|---|---|
| 新接待 | 上传逝者身份证、死亡证明或户口本逝者所在页，不采集预算 |
| 身份识别 | 展示识别候选，代理点击“识别正确，继续”或“有误，修改资料”；确认后即保存基本身份并自动生成基础报价，缺少喜好等不阻塞出报价 |
| 资料补全 | 报价后询问是否根据逝者喜好、习俗调整；点击是才推送可点击进入的完善信息卡片，不展示卡内追问按钮；表单直接展示逝者资料，不显示识别记录、家属关系、逝世日期、告别时间地点。职业、喜好采用下拉选择，选择其他后自行输入，信仰与习俗按意愿补充 |
| 整体确认 | 点击个人信息完善入口，核对后“确认并保存档案”；不保留补传证件或补充并核对的冗余按钮 |
| 报价草稿 | 身份识别人工确认后直接生成基础套餐及材料准备卡片；选择完善个性化资料并保存后自动生成新的待核价套餐 |
| 报价确认 | 代理核价并记录家属确认，原报价冻结；自动提供纪念遗照、电子讣告入口，顺序固定 |
| 服务完成 | 系统登记丧事办理完成后自动提供五七材料准备清单 |

普通接待回复默认1至2句、20至60字，每轮只问下一项缺口。识别确认后直接展示基础报价及个性化追问；选择完善信息后点击摘要卡片进入底部弹窗，不在卡片内继续逐项提问或展示选项按钮。不重复复述按钮已表达的事实；未知不等于无信仰或无喜好，不重复追问已跳过项目。请求期间保留报价和制作卡片，仅禁用冲突操作；失败保留资料并允许重试。

普通接待不加载升单、八字选品规则；生成报价清单时才调用相关建议提示词，缺少可信四柱或已确认偏好不作八字推荐。AI负责提取与建议，系统负责校验保存、计算价格及享年，人工负责核对。不能因AI回复称已经确认、付款、采用或发布。

### 个人信息底部弹窗

点击“个人信息完善”卡片打开底部弹窗，按“基本资料”“喜好与习俗”分组；头部右侧关闭，正文滚动，核对选项与保存按钮固定底部。表单直接展示逝者资料，不显示资料识别内容、家属关系、逝世日期、告别时间、告别地点。职业与喜好下拉选择“其他”后显示自填输入框。已存历史字段不因隐藏而被清空，取消不保存，确认保存后自动重新生成个性化套餐草稿，具体见8.2.1。选择“是，完善信息”后，此卡片在“查看套餐”卡片上方，保持底部弹窗填写方式。

### 对话记录与识别卡片

新接待首句仅显示上传身份证、死亡证明或户口本逝者页的引导，不提前显示个人信息完善卡片。对话按发生顺序展示：上传资料记录→识别回复与资料卡片→代理确认记录→系统确认回复及套餐。识别前后复用同一个卡片结构、字号、间距和样式；点击“识别正确，继续”后保留字段与原位置，仅改为已核对状态、移除底部确认及修改按钮，不抽到顶部或追加另一张不同样式的卡片。

上传、识别确认、选择是否完善、修改资料入口及确认保存等明确提交动作均记录为代理发送的消息，随后接系统回复。点击不再只改变状态而无发送记录；刷新恢复角色和先后顺序。普通查看、关闭、滚动等导航不伪造业务确认，历史未记录的点击不补造成发生过的消息。

### 分阶段客户表单与下载

表单按实际进度推送，代理不手动选环节。已取消或待复核任务不表示进度完成。

| 自动触发进度 | 提供内容 | 展示与数据规则 |
|---|---|---|
| 身份识别资料人工确认 | 基础套餐、办理材料核对单、丧家提前准备清单 | 后两项为与个人信息卡片一致的摘要入口，点击打开底部弹窗，内容区滚动，下载与链接操作固定底部；带入当前代理、机构、电话和当前服务对象资料 |
| 报价核价及家属确认 | 纪念遗照、电子讣告卡片 | 遗照在前；有记录查看进度，无记录进入制作；不设“暂不需要”，旧跳过状态不再隐藏入口 |
| 进入安葬安置且确认相关习俗 | 落土准备与现场核对单 | 读取实际安葬信息，不把拟定安排当预约 |
| 丧事实际完成 | 五七材料准备清单 | 自动提供按需准备内容；宗教、焚烧和纸制用品不默认安排，不表示已预订 |
| 后续关怀且明确需要地方习俗内容 | 排七日期、冥具可选表 | 按家属明确意愿，特殊排法和费用另行核实，不默认购买 |

办理材料核对单只是待备材料，不代表身份资料已确认。办理材料和丧家提前准备清单不含告别时间、地点；出生日期、逝世日期、享年统一取个人信息。详情按服务对象、必需核对项、数量、可选礼俗、代理联系分层展示，PDF使用同一份数据。未知写待确认，不沿用纸单联系人，不编造定金、签字或收款。

保存客户资料后，两份清单立即按当前接待、客户和逝者重算，已打开详情也随最新状态更新，无须重新新建清单。更新姓名、性别、生卒日期、享年、职业、喜好、本人信仰和家属习俗；办理材料仍以办理机构要求为准，不因职业喜好虚构法定材料。准备物品结合明确的信仰与习俗选择、家属已备物品以及当前套餐寿衣更换结果更新；明确不采用传统礼俗时不默认列传统灵堂、供品香烛为准备内容。已备物品标明不重复购买；未知保持待确认。

页面详情、PDF及新生成客户链接复用同一份最新清单。已生成的客户链接属于旧版快照，资料变化后提示更新再分享，不将旧链接误标为最新，也不自动向客户发送。

删除报价下方客户注意事项及其下载入口，不提供独立服务费用核对单、预订单与交接核对单。报价和两份准备清单各自支持PDF下载。生成查看链接不表示已发送，本机链接不表示已跨设备推送。原表地方习俗仅作参考，现场以承办方要求与家属意愿为准。

### 4.1 进入与对话

- 点击首页 AI 接待，每次新建独立接待，旧记录从沟通历史继续。
- 从客户列表点击“继续沟通”，进入该客户、该服务对象的持续记录。
- 对话顶部删除“新客户接待”和“上传资料／核对建档”两块区域；保留标题与沟通历史入口。
- 正文以对话为主；底部保留文字输入、上传加号和发送。
- AI回复面向代理；可直接给家属说的话放在独立“参考话术”中，不混为代理内部指令。
- 先回答当前问题，再补问一个影响下一步的关键缺口。已知事实不重复询问，不因资料暂缺阻止咨询。
- 请求中保留当前消息；失败时不丢失用户已发送内容，不显示底层技术错误，可重新请求。

### 4.2 当前办理与进度

当前办理入口随本轮明确需求或AI明确的下一步出现，每次聚焦一个环节。普通咨询或没有明确环节时不显示额外业务动作卡；个人信息入口、已生成报价及自动推荐客户表单持续可达。已有同类常驻卡片时隐藏重复的当前办理入口，包括套餐报价、纪念遗照、电子讣告。讣告与遗照主动引导在报价确认后显示。

| 本轮环节 | 入口与实际状态 |
|---|---|
| 讣告 | 整理电子讣告；没有草稿则进入新建核对，有记录则查看对应内容 |
| 遗照 | 办理纪念遗照；按无原图、处理状态、已有结果、已采用区别说明 |
| 报价 | 核对套餐报价；无清单时继续整理，有清单时显示当前金额与确认状态 |

入口只引导代理办理，不代表聊天已经执行制作或发布。切换讨论内容后不继续保留上一环节的错误入口。拒绝、暂停或取消某项服务时，停止推动该项。

聊天与办理页的衔接以同一客户、同一服务对象和原接待记录为依据：已有草稿、原图、处理中任务或生成结果时继续对应记录，不因再次进入重复创建。套餐已核对资料后直接展示项目，具体规则见8.2。讣告资料带入和返回原聊天的待完善内容见12.2，不把入口可跳转视为完整衔接已实现。

### 4.3 沟通历史

从接待页打开右侧抽屉，支持按客户姓名与消息内容搜索。选择历史记录后继续原沟通。未关联但有内容的接待保留在历史中；空白草稿不冒充已建客户。不能混入其他代理或不可见客户的记录。

## 5. 信息收集、自动归档与客户管理

### 5.1 自动归档规则

1. 未得到明确逝者姓名时，可以聊天、上传人像，资料随接待暂存，不创建虚构逝者。
2. 得到明确姓名后，将结构化资料同步到待核对客户及服务对象档案；无家属称呼时使用明确的待核对占位，不当作真实姓名。
3. 已关联客户／服务对象优先，不能随模型输出更换到其他对象；已有客户内只复用唯一、完全匹配的服务对象，歧义留待核对。
4. 同一接待后续补充继续写入原档案。空值、未提及、无效字段不覆盖已有资料。
5. 已人工核对内容保持；后续明确资料可补空缺，更正已确认内容需要代理人工核对。
6. 自动归档不自动设置“已人工核对”，不触发发布、采用、家属确认或收款。
7. 电话匹配已有客户时须先满足可见权限；不得为了自动归档跨权限关联、自动合并不同客户。

### 7.3 与聊天资料衔接

当前聊天入口关联客户与逝者，带入姓名、享年及已确认采用的照片；有对应有效草稿时继续原稿。后续需完善已核对档案中的离世日期、告别时间与地点带入：缺失保留待补充，冲突交代理核对，不覆盖已有草稿的人工编辑，也不把拟定时间当成已预约。此项及返回原聊天目前尚未完整实现，详见12.2。AI生成正文仍为可编辑草稿，生成与发布分别处理。

商品推荐、套餐推荐及可选升单须综合逝者已知职业、生前习惯与喜好、本人宗教信仰及家属意愿。职业不推导喜好或消费档次；信仰与仪式需求独立。商品宗教适用标注明确时检查兼容，不推荐明确冲突款；未知信仰优先中性款，不虚构宗教适配或功效。推荐理由说明真实商品特点与明确个人需求的关联，职业和信仰本身不构成升单理由。

## 8. 套餐、报价与参考话术

### 8.1 套餐资料

当前代理版以用户纸单为参考，不用旧商城价格冒充纸单。简朴套餐历史参考价4580元；普通寿衣全套、佛经10包、12寸遗像、简易灵堂、雨棚、净身穿衣及骨灰盒按纸单包含范围核对。骨灰盒原图约1000元的说明不是再收一次费用。

| 增项 | 历史参考价 | 注意事项 |
|---|---:|---|
| 办手续、陪同、下葬全程服务 | 1000元／项 | 核对是否重复，特殊需求另议 |
| 花圈 | 100或200元／个 | 款式、材质另行核实 |
| 18座中巴殡仪馆来回／上山 | 600／800元 | 按人数、路线与实际承办报价确认 |
| 35–52座大客车殡仪馆来回／上山 | 800／1000元 | 按需选择，避免重复用车 |

这些金额是原始资料口径，不代表实时价格、库存或已对家属承诺。代联系事项不默认含费，家属自备不计价。已备或不需要的套餐项目可以取消，但不按其他单品价自动扣减，需重新核价。

### 8.2 三步办理

从聊天进入套餐时，已核对档案直接展示套餐项目，不再要求点击“生成套餐建议”。进入时仅准备纸单参考内容，不自动核价、确认或付款；已有草稿/确认清单按原记录恢复，不重置。资料尚未核对时先提示补充并核对资料。

1. **套餐项目**：通过勾选决定本次包含项，选中表示需要、取消勾选表示不要，不提供取消/恢复按钮；点击商品图片或名称查看商详。删除顶部客户信息块及材质讲解板块，删除家属自备与代联系事项板块，准备事项使用独立清单卡片。
2. **增项核价**：选择增项与数量；显示系统合计及待核价状态。数量为1–100整数，金额有效；勾选已核对价格及范围后才能下一步。
3. **清单确认**：展示项目图片、数量、金额和合计；修改内容自动保存为待确认清单，不提供保存与复制按钮；取得家属同意后记录确认，确认后底部主按钮为下载PDF。

包含项取消、增项数量、已应用的单品替换及补差即时保存到对应接待清单；未核价也可保存草稿，自动保存不等于家属确认。非法数量/金额不写入，并提示当前调整未保存。重新打开恢复已有调整，不回退到默认套餐。

金额由系统计算，不采信模型随口计算的总价。改价、改量、增删项目后，原核价和家属确认失效。确认后的清单冻结，新需求另行处理，不直接改历史快照。未确认仍可按允许规则导出当前草稿，但必须明确待确认，不能冒充已成交或已付款。

参考话术默认折叠。AI说明实际差异、待核实价格与可不选的余地，不通过恐惧、孝心或宗教承诺促单。纸单、模拟材质规则、真实商品资料分开使用。

按需增项页不提供基础套餐价输入框，合计固定在底部左侧，上一步与下一步放在右侧。清单确认页沿用套餐项目页相同高度的单行底栏：左侧合计，右侧上一步及记录家属确认；家属核对选项和核价提示放在可滚动内容区，保留原确认门槛。删除正文下载套餐按钮；确认后底部主按钮改为下载PDF。

### 8.2.1 个性化套餐自动更新

身份人工确认后先生成基础套餐。代理选择“是，完善信息”，填写职业、喜好、信仰和家属习俗并确认保存后，系统调用套餐生成模式，按新资料直接更新当前未确认套餐草稿；不再要求重复点击“确认加入”才能形成新套餐。后续再次修改并保存同样触发更新。

只将有明确资料依据的有效目录项目加入草稿，价格及合计由系统读取目录并计算，模型不能编造价格或补差。每次替换上一次自动生成的增项，保留代理手动选定项目、其他包含范围以及人工更换的商品及补差，不累积重复收费。信仰变化同步宗教用品范围；取消项目不按未知单价自动减价。基础套餐已满足需要时可保持内容与金额，记录本次匹配依据，不为显得更新而强行增项。

生成成功后显示“个性化套餐已生成 · 待核价和家属确认”，查看套餐及PDF读取新草稿和生成依据。重置核价状态，不自动替家属确认；已确认套餐保持冻结。生成中保留原套餐，失败保留资料和原草稿并提供重试，资料已再次变更时不采用旧请求结果。

### 8.3 客户套餐详情与下载

客户详情“套餐”点击打开当前服务对象对应的套餐详情，展示本次商品/服务、数量、单价、小计、包含范围、替换补差、合计及核价/确认状态；不直接触发下载。优先读取该对象保存的代理清单，否则读取当前对象待客户确认的方案或有效正式报价；较新的待确认方案优先展示，不因尚未生成正式报价而隐藏。仅有已生成建议时显示待核价参考方案，不冒充已确认报价。详情固定底部提供“下载套餐 PDF”，代理清单详情可继续进入现场讲解。导出与详情复用同一数据，不重新套用默认套餐覆盖已有方案。

### 8.4 电商式商详与升级替换

点击套餐商品进入电商式商详。页面共用一处主图、价格、商品名称、规格、款式选择、商品介绍及固定底部操作栏；不再上下堆叠两张长商品卡。原方案与可选升级融入“款式选择”，点击切换主图、名称、规格、目录价和待选用状态；切换预览不等于替换。

原方案不显示升级推荐理由，只介绍当前商品；选中升级款后才显示“选款参考”，比较两款产品及八字依据。商品介绍与规格默认完整展示，不设展开／收起。删除“查看完整演示对比”入口。原款有已核实单品价时展示，没有可靠价格时标明“单品价待核实”，不从套餐总价拆造；套餐内已含项目不重复收费。缺实拍图可用明确标注的同类别示意图，不当作候选商品实拍。

商详所有底部操作固定，不随正文滚走。原方案显示当前报价和升级入口；升级款提供“选用此商品”。点击后输入实际替换补差（允许零或合法负数），勾选已核实补差及家属意愿，再“确认替换，更新报价”。目录单价不自动当补差。成功后直接进入更新后的清单确认页，重新核价并取得家属确认；金额无效或保存失败不冒充成功。已确认报价冻结，不直接改原单。

替换写入当前对象的报价草稿，包含新商品名称、商品ID、规格／图片快照和实际补差。套餐项目、套餐详情、客户报价摘要及PDF读取同一份最新草稿；不沿用被替换款的名称，不丢失原有其他项目。再次替换同一项目覆盖该项替换记录，不累计重复收费；刷新恢复以已保存清单为准。

候选仍来自当前机构可用真实目录，同类、宗教适配与已确认偏好优先。职业不直接推导款式或消费能力；五行方向须已确认且商品有对应标注，表层五行数量不等于喜用。已选SKU明确时仅提供符合当前规则的同类候选；原SKU不明不编造升级差异。

推荐说明使用实际AI接口，专用提示词输出60至100字、最多3句：先比较两款真实材质、款式、规格差异，再结合系统按已核对生辰算出的四柱、已确认五行方向与商品明确标注说明关联，最后保留原方案和选择权。缺少原款资料、出生时辰、方向确认或商品标注时如实说明，不凭五行缺项推断喜用，不承诺转运或影响后代。推荐结果不自动修改档案和报价，失败不影响查看商品及人工选择。

演示客户可使用明确标注的虚构规格、生辰及模拟五行方向验收，不冒充真实客户或顾问结论，不写入真实报价。普通客户页不再提供独立演示对比入口。

## 9. 八字资料与讲解

八字模块采用[殡葬八字与礼俗咨询提示词P05](geyou-agent-prompts.md)，重点为逝者资料、礼俗解释及服务选择。普通术语问答不输出个人命盘；只有明确个体分析才使用对应对象资料。日期安排须严格对应目标日期，实际择日与宜忌需要可追溯的历法及当地规则；未接入时不编造，也不代替场地预约。

由系统历法计算四柱，AI只解释系统结果。支持公历／农历、闰月、出生时间地点、零点／23点换日，采用北京时间，不校正真太阳时。

出生时间不详可保存资料，但不补造完整四柱；不能默认使用中午12点。表层五行数量不等于喜用，缺某元素不等于必须购买对应商品。家属明确偏好可记录，不承诺转运、家运或影响后代。

机构尚无正式材质对应规则时，演示映射只对明确的演示客户生效，不进入真实报价和库存判断。正式业务需机构提供可追溯规则与真实商品资料。

### 9.1 独立安葬择吉（一期）

**入口与列表。** 首页入口统一命名“安葬择吉”，仅由首页进入，不接入AI接待流程。先进入统一记录列表，保留服务对象姓名与服务类型；只有完成“保存选择并返回”的记录显示对应结果，时间前标注“安葬时间：”，公墓名称前标注“安葬公墓：”。未确认的临时选择不展示为列表结果。删除日期范围、候选时段数、公墓推荐数、保存状态说明与“已确认”字样；仅选单项的记录只显示该项。“新增”创建独立记录；已有记录可继续调整，旧择吉记录按“择时”兼容。

**服务选择。** 详情仅有“择时”“择位”两个按钮，默认选择择时；可分别选择，也可同时选中，至少保留一项。去掉“同时办理”第三按钮以及两个按钮下的说明。单独择时仅展示日期与候选时间；单独择位展示公墓需求，客户信息仍需完整生辰；两项同时选择时共用客户资料、在同一条记录中保存时间与公墓。服务切换使旧候选和选择失效，需重新生成。

**填写资料。** 点击资料摘要卡片，从底部弹窗选择已有客户或手动填写。客户仅一位逝者时自动带入，多位时再选服务对象。所有服务组合均需完整出生日期、出生时间及逝世日期。字段包括逝者姓名、出生日期、出生时间、公历或农历、闰月、逝世日期与换日口径；不填写出生地，统一北京时间UTC+8，未校正真太阳时。取消弹窗不保存草稿，保存后显示摘要，不写回客户档案。有效公历日期须合法且逝世不早于出生。移除弹窗副标题“选择已有客户，或手动填写”；换日口径直接展示，不再折叠于“排盘口径 · 北京时间”。页面移除“出生时间不详时不补造时辰。北京时间（UTC+8），未校正真太阳时。”说明；这些口径仍按功能规则执行。

**两页流程与布局。** 第一页填写需求，只展示服务选择、客户摘要、日期范围和公墓需求；底部固定“生成择吉方案”按钮。生成成功进入第二页“安葬择吉结果”，顶部展示对象摘要和四柱；同时选择两项时以“择时／择位”两个页签切换，切换不清除选择，单项不显示页签。结果页不混排输入条件，不铺开全局八字择位长分析。中间内容滚动，底部固定选择摘要及“修改需求”“保存选择并返回”，不再单独堆叠“本次选择”正文区。返回修改保留输入，改动后重新生成；通过 `view=needs/results` 区分并在刷新后恢复。工作区占一屏高度。代理端普通下拉框箭头距右侧14px，文字预留42px，覆盖页面及弹窗。

**客户资料校验。** 选择已有客户或手填都要求出生日期、出生时间和逝世日期完整；保存客户信息、生成建议和最终保存均校验。缺项提示具体缺项，并提示“安葬择吉需要根据逝者的出生时间推算”。不补造时辰，校验合法公历／农历、闰月、时间范围及逝世不早于出生。包括“请填写或选择逝者姓名”在内的校验错误统一居中toast展示，约4.2秒消失，不占表单空间。

**日期范围。** 选择客户或保存逝世日期后，默认逝世当日起7天内，含当天，结束为第6天；可手动调整，最大跨度93天。开始日期输入框限制不早于已填逝世日期，结束日期限制不早于开始且不超过开始后的第92天；生成时仍拦截反向范围、无效日期、超过93天及早于出生或逝世的日期。默认七天与93天上限由功能约束，页面不展示“默认逝世当日起7天内，可调整；最多93天。筛选07:00至18:59时段。”提示。范围标题下不重复显示日期区间，保留开始、结束输入框。

**候选生成。** 复用现有历法库生成四柱与黄历数据；日、时均宜安葬且不列忌安葬，并过滤日支、时支与出生四柱地支存在六冲的时段。当前筛选07:00至18:59；出生时间不详不补造四柱；无候选不放宽条件凑数。此为明确规则的初筛，不等同完整流派择吉，未纳入墓向、家属命盘等条件；不承诺唯一最佳或功效。

**八字择时参考。** 结果页四柱排盘默认展开，以一行四列显示年、月、日、时柱，可手动收起；不在其他参考区重复四柱。择时页签先展示候选日期和时段，再直接显示“黄历日、时均宜安葬，且与出生四柱地支无六冲。”摘要。出生地支等详细依据默认折叠；每个日期卡的“推算依据”可展开核对该日地支和各候选时段地支。不把无六冲写成完整流派结论。不显示排盘下方agent-help日期／北京时间说明，移除独立auspicious-rules说明，以及“可供人工确认”“可调整日期范围，再次筛选。”和候选数量操作提示行。

**展示与选择。** 候选按日期分组、时段按钮点选，日期排序不表示优劣。公墓卡片仅显示名称、完整地址及单选控件，保留两家供二选一，仅有一家不凑数；可直接单选，点击名称或地址进入详情，详情底部可“选为意向公墓”。点击时间或公墓先保存临时选择并留在结果页；固定底部摘要持续展示两项所选结果或待选择。只择时需已选时间，只择位需已选公墓，两项同时选中则结果齐全才能“保存选择并返回”；列表仅展示最终保存确认的结果。保存选择不代表园方确认或预约。保存失败留在当前页提示，不假称成功。修改客户资料使两类结果均失效；修改日期仅使时间候选及选择失效，修改公墓需求仅使公墓候选及选择失效，相关变动清除完成状态。需重新生成受影响结果。

**公墓推荐。** 一期推荐整座公墓，不做具体墓穴、墓向或八字风水评分。首批收录杭州南山陵园、半山公墓、钱江陵园、第二公墓、浙江安贤园，数据维护区县、公开地址、咨询电话、简介、资料来源与来源日期；页面展示范围按下方公墓详情规则执行。需求为城市、区县、安葬类型和选填预算上限。先按地区筛选，已知价格或完整葬式资料明确不符合时排除；再调用独立公墓模型，结合系统计算四柱与真实公墓资料输出总分析及2家符合当前已知需求的考察建议，供二选一（仅有1家时不凑数）。模型不得重算八字、补造时辰、以表层五行计数直接判喜用或把园名／地址当墓穴坐向。缺具体坐向或实地地理资料时明确匹配依据不足，不承诺八字相合、风水最佳或影响后代。通常输出2家供二选一，候选仅1家则只输出1家，在公墓详情展示“八字匹配依据”：四柱依据、传统规则、公墓事实、匹配结论。缺少具体坐向、现场数据或可信命理判断依据时必须说明无法证明相符，不以文案包装成证明。输出公墓ID须通过服务端与客户端白名单校验。模型失败保留需求、提示重试，不回退伪造AI结果。未知价格／葬式仍可作为待核实候选，但不计为满足该条件。未收录地区显示空结果，不扩大地区、不虚构公墓。当前尚无可靠在售墓位价格，预算仅用于标出需要核实是否符合，不声称已按预算精确推荐。独立接口 `/api/geyou/cemetery/recommend`；运行提示词真源 `web/geyou-cemetery-prompt.ts`，版本随结果保存，不进入接待消息。资料来源、日期与号码冲突留在内部数据，不在公墓详情展示来源链接、整理日期、待核实事项或电话核验提示。价格、可售情况、购买条件、到访安排由园方确认；未接实时余位、预约及地图距离接口。

**公墓详情与照片。** 详情顶部展示对应公墓实景大图，下方缩略图可切换，显示当前图片序号；照片采用本地静态文件，素材数据保留原始来源，不用其他公墓或生成图片冒充。当前5家共11张照片。图片区下依次展示地址、简介、可拨打咨询电话、推荐理由与完整四段八字匹配依据；不在选择卡片重复展开理由或依据。删除“需要向园方核实”“资料来源”区域、来源日期、电话核验说明及额外提示。不删改匹配结论中的事实边界，资料不足不能被表述为已证明八字相符。

**旧推荐兼容。** 旧版本多公墓结果或缺少当前四段依据的结果不继续显示；需求及原始记录保留，回填写需求页提示重新生成。新结果通常2家二选一，最终只保存1家意向公墓，列表不再显示推荐数量或待更新状态说明，不把旧三家结果当新方案。

**文案与保存。** 公墓推荐列表移除标题下“小字说明”和卡片底部“查看详情与资料来源”／“已选为意向公墓”文字；点击名称或地址进入详情，右侧单选控件直接选择，选中态保留勾选标记。 界面不展示“记录保存在当前浏览器”“保存每一次日期选择与确认”“此处修改不写回客户档案…”“已保存选择结果·需另行核实预约安排”“核对资料，筛选日期，人工确认”等说明；摘要卡不额外显示“客户信息”标签，移除“填写出生资料，用于八字排盘”。页面不展示“可单选，也可同时选中两项。”及“当前收录杭州首批公墓。按地区筛选，价格或安葬方式未明确的会列为待核实候选。”提示。当前实际保存为浏览器本地记录，刷新恢复不等于生产持久化、跨设备或场地预约。

## 10. 提示词与系统职责

详细提示词、变量和示例见[《代理端提示词》](geyou-agent-prompts.md)。提示词不能代替业务权限、价格计算或确认门槛。

| 职责 | 负责方 |
|---|---|
| 理解问题、补问、资料候选、讲解与话术 | AI |
| 权限、关联、归档、幂等、价格计算与业务状态 | 系统 |
| 核对证件及身份、照片采用、核价、家属确认、发布 | 代理按实际情况办理 |
| 场地、礼仪、价格、付款及履约事实 | 以真实业务信息为准，模型不能自行确认 |

知识优先级：当前系统快照和人工确认资料 → 家属本轮明确补充 → 当前接待历史 → 已授权纸单／商品资料。另一客户、假设案例、模型推断不得写入当前档案。缺失、冲突或身份歧义应提示核对。
