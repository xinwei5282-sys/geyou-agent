# 格优代理端 PRD

版本：V1.2｜日期：2026-10-22｜用途：代理移动端产品、研发与验收基线

本卷承接《殡葬服务工作台 PRD》的代理端模块，以当前会话确认的代理端规则为准。产品正文按业务模块组织；提示词见[《代理端提示词》](geyou-agent-prompts.md)。本文描述产品应有行为，当前实现差异和验证范围统一放在第 12 节，不能据此认定已上线。

## 1. 产品定位与目标

面向生命礼仪服务代理及业务员，提供手机优先的接待与制作工作台。以持续对话收集家属需求，将资料、人像、讣告和报价归入对应客户及逝者档案，让代理在沟通中逐步办理，而不是先填写完整表单才能开始服务。

核心结果是：客户与服务对象关联准确、沟通可继续、资料不散落、制作结果可核对、报价可解释。AI负责整理与建议，系统负责保存、计算和校验，代理负责核对和记录家属确认。

| 目标 | 验收口径 |
|---|---|
| 一次点击开始接待 | 首页进入可输入的对话页，不先展示客户卡或上传功能区 |
| 接待信息有归属 | 明确姓名后形成待核对档案；后续资料、人像沿用关联，不重复建档 |
| 当前办理跟随沟通 | 只展示当前讣告、遗照或报价环节的入口，不常驻全部服务 |
| 产物与确认分开 | 生成结果不自动变成家属采用、发布或成交 |
| 金额可复核 | 系统计算合计；核价、家属确认与付款状态分开 |
| 手机可操作 | 在375px、440px等代表宽度，关键按钮可达、页面不横向溢出 |

尚无生产使用基线，不设虚构的使用率、转化率或服务时效。试点时记录接待到建档完成率、重复档案数、人工纠错数及生成失败率，再确定优化目标。

### 1.1 用户故事

1. 作为代理，我希望一键开始对话，在资料不完整时也能先回应家属。
2. 作为业务员，我希望接待中明确的信息和人像进入对应档案，减少重复录入和串档。
3. 作为代理，我希望当前办理随沟通变化，只看到本轮需要处理的事项。
4. 作为业务员，我希望从客户列表继续原沟通，保留已确认资料和历史。
5. 作为代理，我希望先制作遗照、再选择关联，并能核对不同服装结果后采用。
6. 作为代理，我希望讣告信息和服务电话准确，经家属确认后再公开。
7. 作为代理，我希望套餐有可解释的项目、金额和核价过程，不重复收费。
8. 作为家属，我希望得到尊重、克制的沟通，能够拒绝或暂停，不被未经确认的内容代表。

## 2. 用户、权限与数据范围

| 角色 | 使用内容 | 数据边界 |
|---|---|---|
| 代理主账号／老板 | 本代理客户、接待、制作与报价 | 本代理授权业务 |
| 业务员 | 接待、本人获授权客户及关联产物 | 成员模块权限与客户可见范围的交集 |
| 家属／亲友 | 查看已确认并可公开的讣告、联系代理 | 不访问内部聊天、草稿和客户管理 |

代理端复用既有客户与业务数据，不建立第二套机构或客户库。客户联系人与逝者是不同对象；同一客户可以关联多位逝者，各自的照片、讣告、报价及进度必须隔离。界面隐藏不能替代服务端权限校验。

## 3. 信息架构与页面框架

底部主导航仅为“首页／客户／我的”。首页提供“AI 接待／电子讣告／遗照制作”三个入口，不显示“最近沟通”。参考图中的商城不属于当前主导航。

| 页面 | 核心内容与操作 |
|---|---|
| 首页 | 人物主视觉、品牌与标题、三张功能卡 |
| AI 接待 | 对话记录、当前办理入口、输入与上传、沟通历史 |
| 沟通历史 | 右侧抽屉、搜索、选择记录继续；无新建接待按钮 |
| 客户列表 | 客户与服务对象摘要、最近沟通、独立“继续沟通” |
| 客户详情 | 家属联系、逝者资料、人像、告别安排、服务产物、最近沟通 |
| 资料／上传／八字／套餐 | 独立全屏操作页；保留返回及必要底部操作 |
| 电子讣告 | 列表、详情、资料编辑、模板与内容核对、预览 |
| 遗照制作 | 列表、新建、任务详情、原图／结果、关联及采用 |
| 我的 | 当前账号、联系电话、资料权限说明、产品说明（PRD）、退出登录 |
| 产品说明（PRD） | 章节选择、业务规则、验收用例及当前实现边界，只读查看 |

“我的”不提供“我的客户／共享演示／机构完整版”入口。客户详情不重复放置“继续沟通”，该操作留在列表。首页不显示右上角新建按钮，客户列表可新建接待。

顶部标题稳定居中；返回与右侧操作保留对称安全留白。列表和主页面使用底部导航，办理页以任务完成与返回为主。长对话、表单滚动不遮挡输入栏或底部主操作。

添加客户资料时，点击“选择照片”区域弹出来源选择，包含“从相册选择”“拍照”和“取消”；不再在页面常驻两颗同类按钮。相册不指定拍摄模式，拍照入口使用移动端相机捕获；实际系统选择器由设备决定。

### 3.1 空状态

代理端列表与套餐准备页统一使用空状态组件：遗照、讣告、客户、沟通历史和套餐准备，图标尺寸、标题/说明、垂直留白一致。区分没有记录与搜索/筛选无结果，后者提供重置筛选入口。无记录不虚构示例数据，不重复提示点击右上角制作。商品详情没有升级候选时继续隐藏推荐区，不显示空状态。

### 3.2 页面查看 PRD

“我的 → 产品说明（PRD）”打开代理端专项文档，可按章节阅读。页面与本Markdown共用一个内容源，显示版本和更新日期；不另存一份可能过期的文案。查看、返回及切换章节不修改客户或业务记录。总工作台的开发PRD继续显示总纲，两者通过文档索引关联。

## 4. AI 接待与持续沟通

首次人工核对并保存客户资料后，对话展示可跳过的电子讣告与遗照服务提醒。已有记录展示查看或进度入口，不重复新建；必要信息在对应制作流程补充。点击暂不需要后持久保存选择，重新进入或再次保存资料不重复提醒；后续明确提出需求仍可办理。提醒仅提供入口，不代表已制作或家属确认。

### 4.1 进入与对话

- 点击首页 AI 接待，复用可访问的未关联草稿；没有草稿才新建。
- 从客户列表点击“继续沟通”，进入该客户、该服务对象的持续记录。
- 对话顶部删除“新客户接待”和“上传资料／核对建档”两块区域；保留标题与沟通历史入口。
- 正文以对话为主；底部保留文字输入、上传加号和发送。
- AI回复面向代理；可直接给家属说的话放在独立“参考话术”中，不混为代理内部指令。
- 先回答当前问题，再补问一个影响下一步的关键缺口。已知事实不重复询问，不因资料暂缺阻止咨询。
- 请求中保留当前消息；失败时不丢失用户已发送内容，不显示底层技术错误，可重新请求。

### 4.2 当前办理与进度

当前办理入口随本轮明确需求或AI明确的下一步出现，每次聚焦一个环节。普通咨询或没有明确环节时不显示服务卡；不能因“资料已核对”一直显示整组入口。

| 本轮环节 | 入口与实际状态 |
|---|---|
| 讣告 | 整理电子讣告；没有草稿则进入新建核对，有记录则查看对应内容 |
| 遗照 | 办理纪念遗照；按无原图、处理状态、已有结果、已采用区别说明 |
| 报价 | 核对套餐报价；无清单时继续整理，有清单时显示当前金额与确认状态 |

入口只引导代理办理，不代表聊天已经执行制作或发布。切换讨论内容后不继续保留上一环节的错误入口。拒绝、暂停或取消某项服务时，停止推动该项。

聊天与办理页的衔接以同一客户、同一服务对象和原接待记录为依据：已有草稿、原图、处理中任务或生成结果时继续对应记录，不因再次进入重复创建。套餐已核对资料后直接展示项目，具体规则见8.2。讣告资料带入和返回原聊天的待完善内容见12.2，不把入口可跳转视为完整衔接已实现。

### 4.3 沟通历史

从接待页打开右侧抽屉，支持按客户姓名与消息内容搜索。选择历史记录后继续原沟通。未关联但有内容的接待保留在历史中；空白草稿不冒充已建客户。不能混入其他代理或不可见客户的记录。

## 5. 信息收集、自动归档与客户管理

### 5.1 自动归档规则

1. 未得到明确逝者姓名时，可以聊天、上传人像，资料随接待暂存，不创建虚构逝者。
2. 得到明确姓名后，将结构化资料同步到待核对客户及服务对象档案；无家属称呼时使用明确的待核对占位，不当作真实姓名。
3. 已关联客户／服务对象优先，不能随模型输出更换到其他对象；已有客户内只复用唯一、完全匹配的服务对象，歧义留待核对。
4. 同一接待后续补充继续写入原档案。空值、未提及、无效字段不覆盖已有资料。
5. 已人工核对内容保持；后续明确资料可补空缺，更正已确认内容需要代理人工核对。
6. 自动归档不自动设置“已人工核对”，不触发发布、采用、家属确认或收款。
7. 电话匹配已有客户时须先满足可见权限；不得为了自动归档跨权限关联、自动合并不同客户。

### 5.2 资料与人像

| 信息 | 归档位置与校验 |
|---|---|
| 家属称呼、电话 | 客户联系人；与逝者姓名区分，电话格式校验 |
| 姓名、享年、性别、关系 | 服务对象档案；不能由模糊年龄段猜具体岁数 |
| 出生资料、离世日期 | 服务对象资料；日期口径明确，缺失不推算 |
| 告别时间与地点 | 拟定安排；记录不等于场地预约成功 |
| 预算与逝者宗教信仰 | 预算为本次服务需求；宗教信仰记录逝者本人有无信仰及所属宗教，未确认保持待确认，明确无信仰记为无特定信仰。家属信仰、宗教仪式需求分别记录，不由仪式安排推断或覆盖逝者信仰 |
| 识别候选与来源 | 接待资料记录；保留核对线索与冲突说明 |
| 上传人像 | 关联服务对象的照片记录；提前上传的图片在关联后转存一次 |
| 生成结果与采用记录 | 照片任务及对应档案；未采用不替换已确认遗像 |

转存人像必须幂等，重试不产生重复照片；关联成功后清除接待中的重复暂存图片。生成结果、服装版本、原图和已采用记录分别保留。

### 5.3 资料核对与识别

上传区区分证件资料与人像照片，支持相册／拍照选择。当前图片入口限制单张10MB并在处理前压缩与校验。

证件识别提取明确标注的姓名、性别、出生和离世日期，不从证件号码推断资料。展示候选来源与冲突，识别失败允许重拍或手填。证件原图仅临时识别，不保存证件号码、住址、原图或原文件名。

“核对资料 · 建立档案”顶部删除“关联客户”概览块，保留资料填写、识别候选及核对保存操作。代理对照原件核对后勾选确认，再保存。未关联接待如需选择已有客户，可保留实际归属选择，不应与顶部概览块混淆。

### 5.4 客户列表与详情

- 列表仅展示可访问的已归档客户，支持家属、逝者姓名和电话搜索。
- 客户卡片主区域进入详情，独立“继续沟通”进入对应对话。
- 删除“电话待补充／资料待补充／资料已核对／清单待确认／清单已确认”列表状态区域；列表卡片不显示手机号。联系电话保留在客户详情，电话搜索仍可使用。
- 详情展示真实资料和产物，未生成内容只能提供制作入口，不能展示伪完成结果。
- 多位服务对象须明确切换；照片、资料及安排跟随当前对象，不串档。

## 6. 遗照制作

新建遗照页点击上传图标或上传区域，弹出相册/拍照/取消选项，不再展示两颗常驻上传按钮。关联服务档案删除“也可以先上传照片，之后再关联客户和逝者”说明。

列表没有照片时，显示统一照片图标、空状态标题与说明，不保留“点击右上方制作”。

独立首页入口先进入列表，再新建或查看任务；无需先建客户档案即可上传、选服装并生成，制作后可选关联。接待中上传的人像则随该接待归档。

| 环节 | 产品规则 |
|---|---|
| 列表 | 搜索客户或任务名称；按全部、处理中、已完成、失败筛选 |
| 新建 | 上传有效人像，选择服装，可选关联客户与服务对象 |
| 服装 | 保留原衣、唐装、西服、素色正装；家属选择优先 |
| 建议 | 年龄仅作款式建议；未知或不适用成人正装时优先保留原衣 |
| 生成 | 提交真实模型任务；展示处理状态，失败保留原图并允许重试 |
| 结果 | 支持原图／结果对比，清楚区分不同服装版本 |
| 采用 | 明确核对后采用；生成成功不自动采用，不覆盖原有采用记录 |

人物身份一致性优先于美观、表情与服装。保留年龄和个人特征，不承诺侧脸不可见区域的精确还原。默认正式胸像、3:4竖版、浅灰背景，不添加相框、文字或水印。改服装必须重新生成，不能把旧结果当作已换装。

聊天进入遗照时沿用当前客户与服务对象，读取其已有照片及任务。无照片时先上传；已有任务时查看进度或结果。选择照片与服装后的“生成”是真实图像服务操作，与套餐页面已删除的重复准备按钮不同，不能直接省略或用旧图冒充新结果。处理中刷新应继续查询同一任务，完成后刷新、离开重进仍能查看结果；原图与生成图可切换。返回原聊天的路径尚待完善，见12.2。

## 7. 电子讣告

### 7.1 列表与详情

首页入口进入讣告列表，支持按客户或逝者搜索、按全部／草稿／已发布／已撤回筛选。整卡进入详情，缩略图在卡片内保留留白。详情顶部沿用原有背景，预览沿用原文书模板，不改成另一套海报样式。

### 7.2 编辑、预览与发布

- 编辑包括姓名、享年、离世日期、告别时间地点、正文、照片与模板。
- 模板为原有“雅致素笺／素白花语”。先核对关键信息，再核对模板、正文及家属确认。
- AI仅生成可编辑正文草稿；不得补造生平、死因、亲属、信仰或日期。
- 预览明确标记尚未发布；无真实遗像而使用示例时必须标明示例。
- 服务电话使用代理账号电话；详情、编辑、文案生成、预览和公开内容保持一致。缺失时提示补充，不以机构电话冒充代理电话。
- 发布前校验必填信息、关联客户／服务对象、代理电话、当前版本的家属确认及安排一致性。
- 发布同步告别安排的日期时间，发现预约冲突需复核，不把同步记录当作真实预约。
- 已发布内容变更为草稿，须重新确认和发布。撤回、机构停用或安排待复核时，旧公开内容不可继续展示。

花圈只展示代理可提供的商品及联系入口，联系代理后线下沟通，不形成在线支付、配送或结算承诺。

### 7.3 与聊天资料衔接

当前聊天入口关联客户与逝者，带入姓名、享年及已确认采用的照片；有对应有效草稿时继续原稿。后续需完善已核对档案中的离世日期、告别时间与地点带入：缺失保留待补充，冲突交代理核对，不覆盖已有草稿的人工编辑，也不把拟定时间当成已预约。此项及返回原聊天目前尚未完整实现，详见12.2。AI生成正文仍为可编辑草稿，生成与发布分别处理。

商品推荐、套餐推荐及可选升单须综合逝者已知职业、生前习惯与喜好、本人宗教信仰、家属意愿和预算。职业不推导喜好或消费档次；信仰与仪式需求独立。商品宗教适用标注明确时检查兼容，不推荐明确冲突款；未知信仰优先中性款，不虚构宗教适配或功效。推荐理由说明真实商品特点与明确个人需求的关联，职业和信仰本身不构成升单理由。

## 8. 套餐、报价与参考话术

### 8.1 套餐资料

当前代理版以用户纸单为参考，不用旧商城价格冒充纸单。简朴套餐历史参考价4580元；普通寿衣全套、佛经10包、12寸遗像、简易灵堂、雨棚、净身穿衣及骨灰盒按纸单包含范围核对。骨灰盒原图约1000元的说明不是再收一次费用。

| 增项 | 历史参考价 | 注意事项 |
|---|---:|---|
| 办手续、陪同、下葬全程服务 | 1000元／项 | 核对是否重复，特殊需求另议 |
| 花圈 | 100或200元／个 | 款式、材质另行核实 |
| 18座中巴殡仪馆来回／上山 | 600／800元 | 按人数、路线与实际承办报价确认 |
| 35–52座大客车殡仪馆来回／上山 | 800／1000元 | 按需选择，避免重复用车 |

这些金额是原始资料口径，不代表实时价格、库存或已对家属承诺。代联系事项不默认含费，家属自备不计价。已备或不需要的套餐项目可以取消，但不按其他单品价自动扣减，需重新核价。

### 8.2 三步办理

从聊天进入套餐时，已核对档案直接展示套餐项目，不再要求点击“生成套餐建议”。进入时仅准备纸单参考内容，不自动核价、确认或付款；已有草稿/确认清单按原记录恢复，不重置。资料尚未核对时先提示补充并核对资料。

1. **套餐项目**：通过勾选决定本次包含项，选中表示需要、取消勾选表示不要，不提供取消/恢复按钮；点击商品图片或名称查看商详。删除顶部客户信息块及材质讲解板块，保留自备与代联系事项。
2. **增项核价**：选择增项与数量；显示系统合计，超预算提示。数量为1–100整数，金额有效；勾选已核对价格及范围后才能下一步。
3. **清单确认**：展示项目图片、数量、金额和合计；修改内容自动保存为待确认清单，不提供保存与复制按钮；取得家属同意后记录确认，确认后底部主按钮为下载PDF。

包含项取消、增项数量、已应用的单品替换及补差即时保存到对应接待清单；未核价也可保存草稿，自动保存不等于家属确认。非法数量/金额不写入，并提示当前调整未保存。重新打开恢复已有调整，不回退到默认套餐。

金额由系统计算，不采信模型随口计算的总价。改价、改量、增删项目后，原核价和家属确认失效。确认后的清单冻结，新需求另行处理，不直接改历史快照。未确认仍可按允许规则导出当前草稿，但必须明确待确认，不能冒充已成交或已付款。

参考话术默认折叠。AI说明实际差异、预算与可不选的余地，不通过恐惧、孝心或宗教承诺促单。纸单、模拟材质规则、真实商品资料分开使用。

按需增项页不提供基础套餐价输入框，合计固定在底部左侧，上一步与下一步放在右侧。清单确认页沿用套餐项目页相同高度的单行底栏：左侧合计，右侧上一步及记录家属确认；家属核对选项和核价提示放在可滚动内容区，保留原确认门槛。删除正文下载报价单按钮；确认后底部主按钮改为下载PDF。

### 8.3 客户套餐详情与下载

客户详情“套餐报价”点击打开当前服务对象对应的套餐详情，展示本次商品/服务、数量、单价、小计、包含范围、替换补差、合计及核价/确认状态；不直接触发下载。优先读取该对象保存的代理清单，否则读取当前对象待客户确认的方案或有效正式报价；较新的待确认方案优先展示，不因尚未生成正式报价而隐藏。仅有已生成建议时显示待核价参考方案，不冒充已确认报价。详情固定底部提供“下载套餐报价 PDF”，代理清单详情可继续进入现场讲解。导出与详情复用同一数据，不重新套用默认套餐覆盖已有方案。

### 8.4 现场讲解与单品调整

业务员可直接点击套餐项目里的商品，或从清单进入现场讲解，再点商品打开标准商详。顶部只保留返回箭头，不显示“返回清单／返回套餐商品”等重复按钮。页面按商品主图、名称与包含状态、规格、电商式推荐区、商品介绍排列。

推荐区位于商品介绍上方，仅展示一个可选升级商品：左侧主图，右侧名称与目录价格，下方为AI生成的推荐理由。主图读取商品及关联平台商品现有图片；缺图时明确待补充，不使用其他商品图片冒充。没有同类可用升级商品时整个推荐区隐藏，不显示空占位。

候选商品仍按真实商品与客户已记录资料选择：明确喜好优先；职业仅在商品说明有明确对应依据时使用，不按职业刻板推断；五行方向需家属已确认且商品资料支持，不把五行数量当喜用，不承诺功效。已选SKU明确时仅推荐目录价更高的同类候选，原套餐SKU不明时升级差异仍待实物核实。当前主要接入寿衣、骨灰盒类别。

推荐说明使用实际AI接口、专用“商品详情推荐说明”提示词生成，80至140字，具体解释商品特点怎样呼应已知偏好；资料不足时只讲真实特点与比较价值，不输出后台规则、缺口清单或职业刻板判断。结果只展示，不写入聊天、客户档案或报价；上下文变动后失效，离开页面取消请求。

商详删除家属调整需求输入、更换补差、已核对替换、价格预览、确认替换与应用按钮，不在商详修改报价。已有清单中已保存的商品替换与补差继续保留，自动保存及冻结规则不变。

## 9. 八字资料与讲解

八字模块采用[殡葬八字与礼俗咨询提示词P05](geyou-agent-prompts.md)，重点为逝者资料、礼俗解释及服务选择。普通术语问答不输出个人命盘；只有明确个体分析才使用对应对象资料。日期安排须严格对应目标日期，实际择日与宜忌需要可追溯的历法及当地规则；未接入时不编造，也不代替场地预约。

由系统历法计算四柱，AI只解释系统结果。支持公历／农历、闰月、出生时间地点、零点／23点换日，采用北京时间，不校正真太阳时。

出生时间不详可保存资料，但不补造完整四柱；不能默认使用中午12点。表层五行数量不等于喜用，缺某元素不等于必须购买对应商品。家属明确偏好可记录，不承诺转运、家运或影响后代。

机构尚无正式材质对应规则时，演示映射只对明确的演示客户生效，不进入真实报价和库存判断。正式业务需机构提供可追溯规则与真实商品资料。

## 10. 提示词与系统职责

详细提示词、变量和示例见[《代理端提示词》](geyou-agent-prompts.md)。提示词不能代替业务权限、价格计算或确认门槛。

| 职责 | 负责方 |
|---|---|
| 理解问题、补问、资料候选、讲解与话术 | AI |
| 权限、关联、归档、幂等、价格计算与业务状态 | 系统 |
| 核对证件及身份、照片采用、核价、家属确认、发布 | 代理按实际情况办理 |
| 场地、礼仪、价格、付款及履约事实 | 以真实业务信息为准，模型不能自行确认 |

知识优先级：当前系统快照和人工确认资料 → 家属本轮明确补充 → 当前接待历史 → 已授权纸单／商品资料。另一客户、假设案例、模型推断不得写入当前档案。缺失、冲突或身份歧义应提示核对。

| 正式商品与规则 | 纸单为历史参考，演示材质规则不代表机构资料 | 试点前确认当前价格、服务范围、正式地区与材质规则 |

套餐温和推荐和商品详情推荐说明已接入运行提示词。商品推荐理由完成两例本地Codex真实输出验证：有明确棉质传统偏好时解释关联，仅有职业或未确认五行时不强行匹配。HTTP首次请求遇忙碌，CLI验证不代表浏览器自动调用已端到端通过。P01和P05其余规范、输出Schema以及生产接入差异仍需分别处理，不能因文档更新认定已上线。

### 12.3 本期范围外

代理主导航不加入商城、老板看板、完整机构设置、在线支付、交易结算或电子签约；不自动外呼、订场地、收款、推送或替家属确认。不把客户访问、联系点击当成购买成功。

### 12.4 交付里程碑

1. 产品与提示词规范核对：确认本卷及提示词变量、确认边界。
2. 运行契约对齐：完成专用提示词、Schema及字段映射一致性。
3. 真实业务链路验证：新接待→归档→人像→生成→采用，讣告→确认→发布，报价→核价→确认→导出。
4. 试点准备：正式商品与机构规则、生产鉴权和持久化验收。日期与上线承诺另定。
