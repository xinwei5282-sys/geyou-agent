## 1. 产品概述

### 1.1 问题与定位

生命礼仪服务机构的一线人员需要持续了解家属需求、解释办理顺序、选择商品服务、确认清单、登记线下收款并衔接现场事项。照片修复和电子讣告穿插其中，容易发生客户与逝者归属混淆、重复接待、沟通历史分散、报价版本复活，以及预约与公开内容不一致。

产品定位为机构老板与业务员使用的H5服务工作台。以客户持续沟通为主线，以具体服务对象的清单、报价、待办和12环节办理记录承接业务。手机用于日常跟进，平板和电脑用于展示、核对及办理；家属阅读经过确认的对外内容。

### 1.2 目标用户与权限

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 机构老板／主账号 | 查看本店客户、分配负责人、维护企业成员与商品 | 本店业务，不访问其他机构私有资料 |
| 业务员／子账号 | 接待、聊天、选品报价、跟进、办理服务、制作照片讣告 | 已授权模块及有权访问的客户，商品维护权另行配置 |
| 平台维护人员 | 开通机构、配置模块、维护公共商品和地区资料 | 必要平台配置，一期不提供跨机构经营查询 |
| 家属与亲友 | 阅读已确认报价、讣告和安排，联系服务人员 | 不访问内部沟通、负责人、交接和后台操作 |

授权是机构模块、成员权限、客户归属及记录权限的交集。老板与业务员权限有差异；生产接口必须重新校验，不能仅依赖页面隐藏。

### 1.3 目标与衡量方式

| 目标 | 验收口径 |
|---|---|
| 持续沟通不散落 | 同一客户可反复进入；旧聊天与旧接待问答保留，不因成交或换入口重复建记录 |
| 业务归属清楚 | 客户可关联多位逝者；流程、照片、讣告、报价及待办按对应服务对象隔离 |
| 报价与收款准确 | 金额由系统计算，历史快照保留，版本不重复计价，线下收款人工核实 |
| 办理进度可交接 | 环节负责人、预约、进度和交接可保存；无日期不误报逾期，变更需复核 |
| AI与业务一致 | AI读取当前实际业务状态；建议不被当作已经完成的操作 |
| 多设备可操作 | 手机与平板关键入口可达，列表、表单、长对话无横向溢出 |

尚无生产使用基线。试点名单、有效使用次数、日期和效果指标需双方另行确认，不能将演示点击计为真实业务成果。

## 2. 当前范围与历史规则整理

### 2.1 一期范围

- 主线：客户持续沟通、AI对话、服务讲解、本店商品选择、清单确认、逐次成交、总报价与线下收款登记。
- 办理：12环节进度、负责人、预约、交接、待办及阶段维护。
- 内容：照片上传修复、关联和采用；讣告草稿、AI起草、预览、家属确认、发布与撤回。
- 配套：服务档案、历史沟通、企业资料、商品设置、成员与授权。
- 平台配置：机构开通、模块、公共商品和预置地区资料；生产鉴权另列接入范围。
- 经营看板保留已有资料与代码，不作为本轮主导航及重点交付范围。

### 2.2 已统一的规则

| 旧口径／易混淆事项 | 当前采用规则 |
|---|---|
| 每次进入都算新接待 | 进入已有客户复用记录，只有明确新增服务或增购才建立新流程 |
| AI对话与服务沟通各自建一套记录 | 页面独立，底层共用客户及对应服务对象的沟通与业务记录 |
| 两页提供聊天／流程互切条 | 不提供互切条，也不显示“当前服务与流程”独立区块 |
| 清单确认后不能聊天 | 确认只锁定原清单，仍可继续聊天；新增需求通过增购处理 |
| 必须有电话和逝者才能咨询 | 电话及逝者可暂缺，不自动创建虚构逝者；具体对象业务办理前补齐关联 |
| 需要买齐所有项目 | 只处理本次需求；跳过项不收费，已备物品不重复推荐购买 |
| 收款后可直接修改或撤回原订单 | 同一服务已有登记收款时保护历史订单；新增订单仍可确认 |
| 撤回新版后恢复旧版 | 同订单按最高版本判断；最高版撤回不恢复旧成交或旧公开链接 |
| 讣告发布不必同步日期 | 家属确认发布时同步告别日期时间；与实际预约冲突则需重新核对 |
| 照片修复完成就是遗照准备完成 | 必须核对并明确采用；修复结果返回不会自动替换现有用照 |
| 流程仅作讲解 | 可记录实际办理、预约和交接；浏览、购买或付款不自动完成现场执行 |
| 案例单独设置验证入口／选题面板 | 案例直接放在具体测试客户历史对话中，从普通客户入口查看 |

接运不属于本店销售项目，仅作为殡仪馆办理事项讲解，不延伸为全国统一政策或新增免费承诺。公开内容不得承诺亲友花圈在线下单；原型现存演示推荐与正式范围的差异见第6章。

## 3. 用户故事与业务流程

### 3.1 用户故事

| 编号 | 用户故事 | 优先级 |
|---|---|---|
| US01 | 首次资料不全时也能开始咨询，后续再补充 | P0 |
| US02 | 反复进入同一客户能翻看之前记录，避免重复询问 | P0 |
| US03 | 接手客户后，能在权限范围内查看前一位业务员的沟通和办理历史 | P0 |
| US04 | 同一客户涉及不同逝者时，能查看各自流程且不串用事实和费用 | P0 |
| US05 | 成交后还能继续聊天，新增需求通过增购，不改原成交清单 | P0 |
| US06 | 项目、数量、规格和金额清楚，修改有版本和重新确认记录 | P0 |
| US07 | 订金、增补款、尾款分次登记，客户记录与总报价口径一致 | P0 |
| US08 | 先上传照片，查看真实处理状态，核对后再采用及关联 | P0 |
| US09 | 讣告与实际时间一致，家属确认后公开，变更后停止展示旧安排 | P0 |
| US10 | 待办与环节可分配、交接、改期和刷新保留 | P0 |
| US11 | 老板可以授权、转交、启停成员，同时保留历史操作归属 | P0 |

P0表示一期必须达到的行为，不代表生产能力已经验收。

### 3.2 首次接待与持续沟通

新客户接待 → 选择场景并登记已知资料 → 聊天或人工讲解 → 保存当前需求与选择 → 家属确认清单 → 生成本次成交报价 → 持续沟通、办理与跟进。

已有客户进入 → 查看最近消息与历史记录 → 继续聊天或查看对应服务流程 → 按明确需求办理。再次打开、刷新、从档案进入或改用另一入口，不隐式创建补充成交单。

未关联客户时可先聊；后续明确关联客户，保留此前消息。不同同名客户不自动合并，手机号相同提示人工核对，禁止把没有归属证据的记录强行合并。

### 3.3 成交、增购与收款

核对本次清单 → 家属确认成交 → 生成本次报价快照 → 按实际情况登记订金 → 后续明确增购 → 另建成交单 → 总报价汇总 → 核对结算快照 → 人工核实尾款。

成交、收款、实际办理分别维护。保存草稿、浏览、AI建议、分享、家属反馈和结算核对均不自动代表付款；付款也不自动完成服务环节。

### 3.4 照片与讣告

上传并保存原图 → 提交修复／继续既有任务 → 查询终态 → 人工比对 → 关联正确服务对象 → 家属核对采用 → 制作讣告 → 预览 → 核对事实及完整时间 → 家属确认 → 发布／分享。

照片和讣告可独立开始，不作为沟通、报价或付款的强制前置。先修复的未关联照片必须在采用前核对身份与目标档案。

### 3.5 办理与变更

选择具体服务对象 → 进入环节 → 核对关联业务 → 保存负责人、预约、进度与交接 → 待办同步 → 实际完成后确认。

日期或时间变更 → 原安排与冲突内容标为待核对 → 旧公开内容失效 → 核实并取得家属确认 → 更新发布 → 团队复核人员、场地及原安排。系统内部预约不代表外部承办机构已经接受。

### 4.2 页面与列表

客户沟通列表以客户为单位展示姓名、电话、最近消息来源及两行摘要、更新时间和已确认清单标记。整卡继续聊天；对应流程与历史清单入口保留。支持按客户、电话和服务对象搜索，以及全部客户／有沟通记录／待沟通筛选、清空和空态重置。

服务档案列表展示联系家属、电话、重点服务对象、实际阶段、告别时间、下一项待办或待核对情况、负责人和建档日期。待核对及有待办档案优先；无日期待办仍纳入。支持全部服务阶段筛选和对象搜索；筛选某阶段时展示该阶段对应对象，不用其他逝者的阶段替代。告别时间取实际预约，不从过期讣告回填。

两类列表保持统一暖色、清晰层级和触控尺寸；手机单列，平板按可用宽度展示双列。主要操作能通过键盘访问，搜索、长文本、空态和筛选不造成页面横向溢出。

服务沟通与AI页面保持独立，不提供“聊天／沟通流程”互切控件，不显示“当前服务与流程”独立区块。删除显示区块不改变底层客户、服务对象、流程和消息关联。

### 4.3 历史沟通与接手规则

- 完整保留客户此前聊天、旧接待问答和各次服务记录，不以成交、增购或入口调整为由清空。
- 有权访问该客户的接手业务员可翻看原记录；原操作归属保留，不改写为接手人。
- 同一客户不同服务对象的历史可在客户对话中标识展示；当前AI请求只使用指定对象的上下文，不串用其他逝者或其他客户事实。
- 已成交后聊天只追加消息，原清单、报价、收款和现场办理状态不被回复改写。
- 未关联咨询、旧问答和历史清单均保留可访问入口；关联必须明确，不按同名推断。
- 原未关联业务归档到客户时，原有分次收款和结算范围随关联保留，不丢金额、不重复累计。

### 4.4 AI回答与业务一致性

AI读取的系统业务快照包含有权限范围内的实际服务阶段、成交状态、完整预约时间、遗照采用、有效讣告及复核状态、有效成交与登记收款、已有待办。选购页面浏览到的步骤不等于实际服务阶段；未提供的字段为未知或无权查看，不得补造。

| 情形 | 回答要求 | 不得发生 |
|---|---|---|
| 已成交后新增需求 | 继续沟通，说明通过增购处理并核对重复项目 | 直接改原成交清单，要求重新接待 |
| 家属说已转账 | 区分口述与系统登记，要求人工核实到账 | 宣称系统已结清、自动写入收款 |
| 修复图已返回 | 提醒身份与细节比对、家属明确采用 | 将修复完成当作准备遗照已完成 |
| 讣告时间与预约冲突 | 提醒停止分享、修改并重新确认发布 | 直接宣布已更新、已发布 |
| 已有同一服务待办 | 指引查看处理原事项 | 宣称已创建，或重复引导建立相同事项 |
| 请求另一客户／虚构案例参考 | 作为参考回答，不写入当前客户事实及待办 | 挪用其他家庭事实、费用与安排 |

AI输出分为回复、业务员对客话术、已确认／待确认／已备／下一步摘要、商品建议和待办建议。话术要能直接用于家属沟通，克制、具体、有同理心；不把内部记录术语机械拼给家属，不根据职业推断支付能力，不利用悲伤施压。

推荐仅引用有效目录，金额由系统核算。已确认清单涉及历史下架商品时保留快照，不因此阻断继续聊天，也不将其作为新可售商品。待办须业务员人工确认负责人和时间后保存，AI回答本身不创建待办。

### 4.5 报价、收款与版本

- 客户明确确认本次项目和金额后登记成交并生成本次单。未成交报价、草稿、分享及反馈不计累计成交。
- 同一订单以最高版本判定有效性，历史金额和内容不覆盖；最高版撤回后，旧版不重新进入总报价，也不恢复公开访问、确认成交或修订入口。
- 同一服务有登记收款后，原订单不得直接修改或撤回，旧编辑页也不能绕过。仍允许新增订单人工确认成交。
- 总报价按机构、客户和服务对象隔离；客户级未关联对象的单不混入其他逝者。未关联线索的续谈按同一来源链处理。
- 金额按分计算。分次登记要求实际核实、有效金额日期、方式、类型和备注；重复提交去重，拒绝零负数、非法金额及超余额登记。
- 客户相关记录展示分次收款的金额、日期、方式、备注及经办人；累计金额与服务安排收款笔数使用同一范围，旧版本收据按订单去重。
- 历史已撤回订单的收款不能隐藏。超出有效成交时显示异常并要求线下核对退款或订单，不自动模拟退款。
- 结算快照独立保存。增购、版本、项目或收款变化后须重新核对；确认结算不等于实际收款。
- 未开通报价收款权限时，档案基础和服务安排仍可使用，财务区显示权限提示，不执行无权读取导致白屏。

### 4.6 12环节办理与待办

环节为：业务接洽、净身穿衣、死亡证明开具、灵堂布置／送殡仪馆、火化预约、讣告发布、吊唁接待、出殡、告别会、火化、下葬、后续关怀。具体渠道、材料及地方习俗须按实际情况核实，不将流程说明变成统一政策承诺。

环节按客户与逝者隔离，沟通中的业务办理与档案服务安排共用记录。可保存负责人、预约、未开始／进行中／已完成／无需办理和交接说明；完成或无需办理必须指定有权负责人并填写说明。保存同步同一内部待办及跟进，重复保存不重复建单。

无日期事项显示时间待定，计入待办列表和数量，但不算逾期。流程任务通过“去处理”进入对应环节，不能用通用快捷完成绕过业务校验；普通手工事项可人工确认完成。内部任务不向家属公开。

照片采用和有效讣告发布依据真实关联记录回写待办；仅生成照片或保存不完整讣告不得提前完成。讣告撤回、退回草稿或安排冲突后，相关任务重新待核对。整体服务阶段由人员核对推进，不因浏览、买单或付款自动结束；有未完成或待核对事项时不可结束服务。

### 4.7 照片修复

支持PNG／JPG／WebP，入口上限10MB。保存原图，按真实异步任务展示状态；离页不取消，重进恢复查询，不因短暂查询失败重复提交。显式取消及后台终态必须真实回写。

普通上传和未关联照片也可启动修复、取消与关联。列表整卡进入详情，不展示冗余操作按钮或原始服务报错；必要的继续修复、关联和采用操作在办理详情中可达。

从待办进入时按记录分流：无照片进入新建，已有原图继续修复，处理中查看进度，有结果查看核对，失败重试，已采用查看结果。固定当前客户与逝者，保留返回任务来源，不重复上传或串入旧照片。

生成结果须与原图核对身份、年龄、服装及五官。人工明确采用后才作为有效用照；不得把原图、占位图或未完成任务当作真实修复成功。已有用照和已发布讣告照片不随新修复结果自动替换。

### 4.8 电子讣告与时间一致性

发布核对姓名、享年、离世日期、完整告别时间地点、正文与服务电话，记录家属确认；遗照选填。人工修改事实或正文后需重新确认。更换对象清理旧资料和照片，公开版本保存独立用照快照。

从待办进入时按状态分流：无记录新建、缺项草稿续编、完整草稿核对发布、有效发布看详情、撤回或安排变更重新编辑；复用本次有效记录，不重复创建，不拿旧公开讣告替代当前草稿。

告别安排比较完整日期与时间，同日改时也将冲突已发布讣告置为待核对并关闭公开内容。家属重新确认发布时，同步既有告别预约和提醒，保留团队复核提示，不自动完成现场环节。

公开页仅展示有效发布、已家属确认、当前版本且时间一致的内容。草稿、撤回、待复核、已被替代及停用机构的相关公开内容不可继续展示；机构停用同时关闭公开报价与家属安排。

独立预览使用当前表单，不写草稿、不发布、不计公开访问；本机临时预览两小时失效。讣告不展示收款码或其他二维码。正式公开访问、权限与撤回保障依赖服务端方案。

### 4.9 客户版流程分享

业务员预览并核对后，生成固定版本只读链接，家属无需后台登录即可阅读并转发。展示流程、明确时间地点、准备清单与服务电话；不外发内部交接、负责人、家属联系方式和内部费用核对。

当前流程分享原型期限7天，支持停止分享；变更后重新核对并生成，不默默改变已经确认的分享快照。本地接口有独立浏览器读取验证；外部使用仍需要可访问部署地址和配套服务。

### 4.10 客户对话中的案例

“沟通验证案例（测试）”作为具体测试客户出现，包含成交后增购、口述付款、修复后采用、讣告时间冲突四组历史问题与此前本地Codex真实回答，不设置独立入口横幅、选题面板或参考回答区。

业务员从普通客户列表进入即可翻看并继续聊天。已有追加消息保留，旧案例只迁移一次，刷新不重复插入，不改变报价和收款。历史实测回答是保存的记录，不表示本轮重新调用或生产稳定性承诺。

### 4.11 代理移动端

代理端独立入口为`/agent`，共用授权范围内客户、逝者、沟通、照片和讣告数据。详细页面、业务、数据与验收规则统一见[《格优代理端 PRD》](geyou-agent-prd.md)，提示词见[《格优代理端提示词》](geyou-agent-prompts.md)，本节不再复制容易漂移的逐页规则。
