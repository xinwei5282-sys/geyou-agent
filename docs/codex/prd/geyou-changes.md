## 1 改造结论

保留现有 React/Vite H5、Express 后端及 MySQL 的工程基础，复用页面样式、商品管理、员工登录、预约信息和模型调用代码。产品主入口转为代理老板与业务员的经营工作台，客户通过分享页面查看报价、讣告及花圈联系信息。

本次不是单纯换品牌：需要补齐代理数据隔离、AI 动态套餐生成、客户确认与最终报价三项核心能力，并修改现有看板与交易路径。

本文中的“可复用”表示已在源码中找到实现，不表示已验证线上可用。已有 TypeScript 检查通过；数据库、模型调用及图片服务尚未完成独立环境联调。原5186预览仅转发公开展示资料，不支持真实业务写入。

## 4 必须新增的能力

### N1 代理归属与服务端数据隔离

- 增加代理及成员关系，所有私有业务对象具有代理归属。
- 服务端按当前账号验证数据范围，不相信前端传入的代理 ID。
- 老板看本店全部客户；业务员默认看本人负责客户；商品维护权限单独授权。
- 公开报价和讣告只返回允许展示的字段，不能通过改 ID 访问其他代理的私有记录。
- 旧数据迁移需明确归属，不能默认开放给所有代理；首轮采用独立数据库验证迁移。

此项是 R2 至 R8 的共同基础，不能仅通过复制菜单或前端筛选实现。

### N2 公共商品选用与代理可售目录

- 格优公共商品与代理本地商品分开，保留来源关系。
- 代理选用公共商品后，维护本店对外报价和可提供状态。
- 自有商品和服务统一参与 AI 组合，服务有明确计价单位。
- 规范数值价格；“起价”等展示文本不能直接参与核算，缺价不能按零元处理。
- 公共资料更新不自动覆盖代理已确认价格和历史报价。
- 首版不做实时库存、采购、补货或服务排班。

### N3 地区习俗预置与调用

- 预置适用地区、习俗说明、必备项目、禁忌、确认人及版本。
- 代理有默认服务地区，谈单按实际服务地区调用已确认内容。
- 未覆盖地区或缺少必要项目时提示人工确认，AI 不自行补造。
- 首版用导入或受控维护完成，不建设代理自助习俗后台。

### N4 动态套餐、客户确认与最终报价

这是本次最大新增功能，包含一条完整流程：

`客户需求 → AI 组合本代理商品及服务 → 服务端校验与核价 → 人工调整 → 与客户确认 → 最终报价 → 分享或打印`

- 新增结构化套餐草稿和行项目，记录项目、数量、价格、说明与提醒。
- AI 只输出有效项目引用及建议，金额由系统计算；库外商品、停用商品、非法数量等应被拦截。
- 业务员记录客户确认的版本、时间及备注，首版建议不新增电子签署。
- 最终报价保存快照和编号，商品调价不影响旧报价。
- 确认后再修改需重新确认，生成新版本；重复点击不能重复创建同一报价。
- 分享页和打印版仅显示对外报价，不暴露内部备注或成本。
- AI 服务不可用时可重试或人工组合，不能把失败显示为已生成。

### N5 讣告公开链接与代理联系关联

- 讣告发布时绑定代理，公开访问无需员工登录。
- 使用不可枚举的分享标识，支持撤回，避免泄漏后台记录。
- 花圈页从讣告归属确定代理；电话、二维码、花圈项目均来自同一代理。
- 允许保存二维码或拨号，不产生线上订单、支付或结算记录。

### N6 遗像修复

- 新增上传、提交处理、处理中、成功预览下载、失败重试。
- 接入真实修复服务；未配置接口时明确不可用，不能以原图或占位图伪装修复成功。
- 原图与结果按代理和使用者权限访问，默认不公开。
- 接口可用性、费用承担和额度需在第一天核实；这是4天冲刺的外部依赖。

#### 2026-10-09 上传与关联流程补充

- 首页照片修复入口直接进入上传页；上传前不要求先建客户或逝者，也不自动创建虚构档案。
- 未关联照片及其修复状态、原图、结果和模型版本保存在本地工作区；可立即调用真实修复服务，之后再关联当前账号可见的客户和逝者。
- 关联时完整转入照片及修复结果；沿用现有机构、员工模块和客户可见范围权限。既有客户/逝者关联照片继续可用。
- 异步修复任务编号与状态随记录保存；离页仅停止轮询，重新进入后继续查询。用户明确取消时调用取消接口；查询网络错误或服务端暂时错误时继续轮询。

### N7 可追溯的业务记录与统计

- 保存跟进、客户转交、人工确认成交、报价生成等时间和操作人。
- 同一客户多次报价按客户去重；报价主单与修订版本分别统计。
- 客户转交不改写历史业务员操作记录。
- 浏览、二维码展示及拨号点击形成事件记录，排除后台预览和重复上报。
- 指标清楚标注人工确认、当前存量或期间新增，不把点击当作联系成功或成交。

## 5 格优版停用或后置的能力

这里指在格优版中移除入口并关闭对应业务调用，不是删除原项目生产数据，也不是破坏原版功能。

| 旧功能 | 格优版处理 |
|---|---|
| 小程序支付、购买套餐、花圈线上下单、支付订单、账单提现 | 不启用；前端入口和后端写入能力同时控制，不能只隐藏按钮 |

| 客户预约自动产生订单 | 改为客户关联方案和报价 |
| 数字人、语音播报、视频、八字帮选主流程 | 不进入格优首版主导航；AI 依据已确认地区习俗和需求生成方案 |
| 悼词、挽联等其他 AI 文书、云端追思互动 | 首版仅保留讣告模板；其他功能后置 |
| 履约工单、复杂项目管理、账务结算、完整知识库 | 首版不启用 |
| “成本价1.15倍”等旧界面规则、默认15分钟回复承诺 | 未经本次确认，不带入格优产品规则或对外文案 |
| 格优跨代理经营看板 | 后置；基础开通、公共商品及地区数据维护仍需有操作方式 |

### 9.5 完整验收边界

1. 业务员可在H5登录，选择客户，从本代理商品服务生成套餐，调整并记录客户确认，保存和分享或打印最终报价。
2. 两个代理的数据互不串用；有权限者才可维护商品；业务员默认只能处理本人客户，老板可转交。
3. 客户不自动变订单，报价不自动变成交；最终报价快照不受商品调价影响。
4. 看板每个指标有真实数据来源，时间范围和去重明确，不含营业额或演示数值。
5. 讣告能发布分享和撤回，花圈联系信息固定属于正确代理，无线上支付或订单路径。
6. 遗像修复真实可用，异步状态和失败重试明确，私有照片不能跨代理访问。
7. 商品资料、地区习俗、联系方式、模型及修复接口尚未验证的部分单独标记，不能以界面存在替代业务验收。

本节共16项新增、18项修改、11项格优版移除、8项后置。它们是功能行为分类，不是53个独立页面，也不能直接按条数估算开发天数。
